# Proposal: plain-markdown compatibility (0.6.0)

**Status:** implemented on `0.6.0-plain-markdown` — M1 (relative links,
README-as-index, implicit images + content-dir assets), M2 (footnotes,
comment stripping), task lists, and the compatibility docs page
(en/de/fr/es) are all on the branch, verified against a naive corpus.
Setext headings remain unsupported by decision.
**Goal:** markdown written for other tools (GitHub READMEs, VSCode
conventions, existing doc folders) renders correctly when pointed at
open-docs, without rewriting a single line. BYOMD stays the pitch.

## Verified gaps (tested against a naive corpus)

1. **Relative links.** `[setup](./guides/setup.md)`, `../dir/file.md`,
   `other.md#anchor` are what editors auto-complete and validate.
   Resolve them at render time in the store, relative to the linking
   file: strip `.md`/`.markdoc`, map `index`/`README` to the folder URL,
   keep the anchor, run the result through the existing dead-link
   validation. Authors never rewrite links; site-absolute paths keep
   working unchanged.
2. **Images render through the Screenshot component (decided).** Every
   markdown image — `![](./images/x.png)`, a `/static` path, or a web
   URL — renders inline via the screenshot component implicitly (flat
   variant), like an editor preview; never as a bare link out. Relative
   srcs resolve against the linking file and co-located assets are
   served from the content directory (extension allowlist,
   traversal-guarded). Web URLs pass through; validation skips them.
   Anyone wanting the framed look rewrites to the dedicated block.
3. **Task lists.** `- [ ]` / `- [x]` → disabled checkboxes. DONE on this
   branch (store-side item transform, both tight and loose lists,
   fixture-tested). Makes the existing README claim true.
4. **Footnotes.** `[^1]` renders literally today. Implement as a source
   pass (like heading anchors): collect definitions, render references
   as superscript links and definitions as an end-of-page list.
5. **Raw HTML: never rendered (decided).** open-docs is a SvelteKit
   site, not HTML patchwork — inline HTML stays escaped text exactly as
   the author typed it (authors who want to SHOW markup put it in a code
   fence themselves). No allowlist, no execution, ever. Document this as
   the contract.
6. **HTML comments.** `<!-- … -->` is common in existing markdown;
   verify they never render and strip them if they do.
7. **README.md as folder index (decided).** Treated like `index.md`
   when no index exists.
8. **Autolinks: won't fix (decided).** Bare `https://…` text stays
   plain text, per CommonMark. Linkifying automatically would take away
   the author's ability to show a URL without making it clickable —
   links are an explicit opt-in (`[text](url)` or `<url>`). Documented
   as a known limitation with rationale.
9. **Setext headings** (`===` underline) get no anchor ids today — the
   heading-anchor pass only reads ATX. Either support or document.

## Non-goals

Wiki-links (`[[page]]`), emoji shortcodes, definition lists, and ANY
raw-HTML rendering (see 5). Tools that need them can pre-process; open-docs
stays strict-CSP and spec-lean.

## Milestones

1. Relative link + image resolution incl. content-dir asset serving,
   README-as-index (the migration blockers).
2. Footnotes; comment stripping; setext-heading decision; document
   the autolink and raw-HTML stances on the new compatibility page.
3. Docs: a "Bring existing markdown" page (en/de/fr/es); README claims
   audited against reality.
