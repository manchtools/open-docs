# Proposal: blog mode (0.5.0)

**Status:** draft, for review
**Goal:** let any content section opt into chronological, blog-style
operation — posts, listing, authors, tags, feeds — as a layer on top of
docs mode. One container serves docs and any number of blogs from one
content tree; a site that never opts in changes in no way.

## Design principles

1. **Per-section opt-in, zero ambient cost.** Like i18n (no suffix → no
   prefixes), a tree without `blog: true` behaves byte-for-byte like
   today. All blog behavior derives at boot in the content store — no new
   pipeline, no build, no mode switch.
2. **Multiple blog sections are first-class.** `blog/`, `changelog/`, and
   `advisories/` can coexist, each with its own listing, feed, and tags.
   A per-product changelog is the same feature as the blog.
3. **Frontmatter is the source of truth.** The date lives in frontmatter
   as `date: YYYY-MM-DD` (decided); filenames are free-form and slugs
   follow the existing rules. No date-in-filename convention.
4. **New components are ordinary registry tags** — usable in docs pages
   too. Only the *automatic* behaviors (sorting, listing, byline,
   cover-hero, feeds) are gated on the section being a blog.

## Content model

```
content/
  01-getting-started/            ← docs section, unchanged
  09-blog/
    index.md                     ← blog: true (+ intro prose, hero, …)
    open-secret-launch.md        ← a post
  10-changelog/
    index.md                     ← blog: true — a second blog section
    v0-4-0.md
```

### Section switch (`blog/index.md`)

```markdown
---
blog: true
label: Blog            # existing keys keep working
---
```

### Post frontmatter contract

| Key | Required | Meaning |
|---|---|---|
| `title` | as today | post title (falls back to filename) |
| `date` | **yes** | `YYYY-MM-DD`; sort key (desc) and displayed, localized per page language |
| `description` | no | listing excerpt + meta description (falls back to first paragraph, as today) |
| `author` | no | display name, or a site-absolute path to an author page (`/blog/authors/paul`) |
| `tags` | no | comma-separated list → chips, tag pages, related posts later |
| `cover` | no | image under `static/` → full-bleed hero on the post, card image in the listing, **per-post `og:image`** |
| `draft` | no | `true` → served in dev, excluded in production (listing, nav, search, sitemap, feeds) |

Existing keys (`label`, `order`, `meta`, `description`) keep their
meaning; `order`/`NN-` prefixes are ignored for sorting inside a blog
section (date wins; same-date ties break by title descending, so
v0.4.0 sorts above v0.3.3 on a multi-release day).

### Authors are pages (no registry file)

Everything derives from Markdown — including authors. `author:` accepts
either a literal display name (zero setup, no avatar) or a site-absolute
path to an author page:

```markdown
---
title: Why E2EE              # in a post
author: /blog/authors/paul
---
```

```markdown
---
title: Paul Dotterer         # in blog/authors/paul.md — an ordinary page
avatar: /authors/paul.png    # under static/
---

Builds manchtools. Markdown bio, rendered like any page.
```

The byline takes the name from the author page's `title`, the image from
its `avatar:`, and links to the page — so every author has a profile page
for free. A `author:` path that doesn't resolve is a boot error
(fail-closed, like dead links). Pages inside a blog section's `authors/`
folder are not treated as posts (no `date:` required, excluded from the
listing/feeds).

## Derived behavior (the store does all of this at boot)

- **Ordering:** posts sort `date` desc; the sidebar group lists them in
  that order; the section heading still links to the index.
- **Listing:** the blog index renders the author's `index.md` prose, then
  a generated reverse-chronological list — cover, title, localized date,
  description, byline, reading time (words ÷ 200). Generated exactly like
  the home hero: server-derived data, a component, no file to maintain.
- **Prev/next:** within a blog section the chain is chronological and
  labeled **Newer / Older** (two new ui-strings keys, translated like the
  rest of the chrome). Blog and docs chains never bleed into each other.
- **Reading time + byline:** computed/assembled per post; the byline uses
  the same Avatar component authors can place manually.
- **Validation (fail-closed at boot, file:line):** missing/invalid
  `date`, unknown author id, `cover` file not found under `static/`
  (same check as screenshots), and the existing link/anchor/tag checks.

## Generated routes

- **Feeds:** `/<section>/feed.xml` (Atom; one per blog section, and per
  language: `/de/blog/feed.xml`) — a store-backed `+server.ts` exactly
  like sitemap/llms.txt. Absolute URLs need `PUBLIC_SITE_URL`, as today.
  The layout advertises `<link rel="alternate" type="application/atom+xml">`
  on blog pages.
- **Tag pages:** `/<section>/tags/<tag>` listing pages, synthesized from
  the store (no md files). `listPaths()` includes them, so sitemap and
  the search index cover them automatically.

## SEO

Posts extend the existing `<Seo>` head: `og:type=article`,
`article:published_time` (+ `article:author` when known), and `cover` as
the page's `og:image`/`twitter:image` (falling back to the global
`/og.png`). sitemap.xml and llms.txt pick posts up via `listPaths()`
unchanged; llms.txt entries in blog sections carry their date.

## New components (registry tags, auto-schema as usual)

- `{% hero src="…" title?="" subtitle?="" %}` — full-bleed image header.
  Also used implicitly when a post sets `cover:`. (Layout note: breaking
  out of the prose column needs contained full-bleed CSS that respects
  the TOC column.)
- `{% avatar src="…" name="…" description?="" url?="" %}` — image +
  name + bio; doubles as the automatic byline.
- `{% quote by?="…" cite?="…" %}` — styled pull-quote with attribution.
- `{% gallery %}` — image grid (nested list of images, like filetree);
  clicks feed the existing lightbox.

## i18n

Posts translate like any page (`my-post-de.md`), untranslated posts fall
back to the default language, listings show translated titles and
descriptions via the existing overlay, dates format with
`Intl.DateTimeFormat(lang)`, and each language gets its own feed. Tag
slugs stay language-agnostic (the tag string is shown localized only if
the translated post redefines `tags:` — default: shared tags).

## What does not change

Search (posts index at boot like any page), theme.css, runtime env
config, validation pipeline, deployment, the docs sections themselves,
meta/legal pages, BASE_PATH handling. No new container modes.

## Out of scope (backlog)

Related-posts block (cheap once tags exist), series navigation, listing
pagination (matters past ~50 posts), comments embed (giscus/utterances —
needs CSP widening, opt-in), share buttons (intentionally never).

## Milestones

1. **Core model:** `blog: true`, date contract + validation, chronological
   sort, Newer/Older, drafts; store tests on a blog fixture tree.
2. **Listing + components:** generated index listing, hero (tag +
   cover-hero), avatar/byline, quote, gallery; SSR parity tests.
3. **Tags + feeds + SEO:** tag pages, Atom feeds (per section × language),
   article meta + per-post og:image; full-content validation stays at
   zero errors/warnings.
4. **Docs + dogfood:** authoring page ("Blogging"), reference updates
   (frontmatter table, tags), AGENTS.md contract, translations
   (de/fr/es); convert this repo's release notes into a `changelog/`
   blog section as the live demo.

Estimate: ~1.5–2 weeks at the 0.4.0 standard (test-first, CDP-verified,
container-proven). Rough effort split: M1 3 d, M2 4 d, M3 3 d, M4 2 d.
